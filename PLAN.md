# ПЛАН МИГРАЦИИ ПРОЕКТА SimpleOPDS с Python Django на Java 21 Spring Boot

## 🎯 Цель
Перенести функционал SimpleOPDS с Python (Django, SQLite/Postgres) на Java 21, с использованием Spring Boot 3.x, Postgres, Lombok, Thymeleaf, Gradle 8.14, Groovy, Flyway, с плагинами для конвертации и Telegram-бота.

**Критерии успеха:**
- Пользователь не ощущает миграцию (интерфейс, API, структура БД и поведение — максимально идентичны).
- Существующая БД seamlessly подключается к новому приложению (Postgres).
- Ядро на Java, расширения (конвертеры, Telegram) — через плагины.

---

## 🚦 ЭТАПЫ МИГРАЦИИ

### 1. Подготовка и анализ (неделя 1)
- [ ] Детальный анализ текущих моделей Django и структуры БД (экспорт схемы и фикстур).
- [ ] Оценка нестандартных моделей/полей, зависимостей, бизнес-логики.
- [ ] Документирование параметров конфигурации проекта.
- [ ] Оценить и утвердить “живой” экспорт схемы Postgres из Django для совместимости.

### 2. Инициализация проекта (неделя 1)
- [ ] Инициализация Spring Boot проекта: Java 21, Gradle 8.14 (Groovy DSL).
- [ ] Добавить зависимости: spring-boot-starter-data-jpa, spring-boot-starter-web, spring-boot-starter-thymeleaf, lombok, flyway, postgresql, spring-boot-starter-security, spring-boot-starter-validation, spring-boot-starter-test.
- [ ] Настроить описание/чистую структуру проекта, конфиги application.yml.

### 3. Моделирование данных и миграция схемы (неделя 2-3)
- [ ] Описать Entity-классы (JPA + Lombok) в соответствии со схемой Django/существующей БД.
- [ ] Описать связи (ManyToMany, OneToMany, FK...) — соблюсти соответствие Django ORM.
- [ ] Сделать начальные Flyway миграции с поддержкой “чужой” БД.
- [ ] Обеспечить seamless старт на уже существующей БД (миграции допускают NOOP, если схема есть).
- [ ] Тестирование загрузки данных из старой базы.

### 4. Репозитории и сервисный слой (неделя 3-4)
- [ ] Создать JPA Repositories для всех сущностей (Book, Author, Genre, User, Settings и т.д.).
- [ ] Создать сервисный слой (UserService, BookService и т.д.), повторяющий бизнес-логику Python-проектa.
- [ ] Реализовать работу с деревом жанров, кеши, soft-delete и логику видимости.

### 5. Аутентификация и авторизация (неделя 4)
- [ ] Реализовать Spring Security Basic Auth (модель пользователей идентична Django).
- [ ] Реализовать собственный UserDetailsService, подкладывающий пользователей из существующей таблицы users.
- [ ] Поддержка авторизации для API, OPDS и UI (аналог Django).

### 6. REST и OPDS контроллеры (неделя 5-6)
- [ ] Реализация REST-контроллеров для работы с книгами, жанрами, пользователями.
- [ ] Реализация OPDS 1.2 XML-контроллера, обеспечивающего тот же API, что и у Python-версии.
- [ ] Заложить каркас для OPDS 2.0 (на перспективу).
- [ ] Тестирование совместимости с внешними клиентами (Moon+ Reader и др).

### 7. UI-шаблоны и админка (неделя 6)
- [ ] Создать страницы управления библиотекой на Thymeleaf: лента книг, поиск, фильтры, деталка, загрузка/скачивание, админка.
- [ ] Сформировать структуру шаблонов так, чтобы оригинальная навигация, фильтры и лейаут были по максимуму узнаваемы.
- [ ] Страницы настроек, логи, перевод языков (multi-language через Thymeleaf + message bundles).

### 8. Механизм плагинов для конвертации и Telegram (неделя 7)
- [ ] Продумать общий SPI-интерфейс для плагинов конвертации (fb2→epub, fb2→mobi и др).
- [ ] Реализовать загрузку и регистрацию внешних конвертеров (“по конфигу” или classpath discovery).
- [ ] Вынести Telegram Bot в отдельный модуль/плагин (JVM плагин или отдельный microservice).
- [ ] Зарегистрировать/включить Telegram Bot через конфиг.

### 9. Real-time сканер и файловый анализатор (неделя 8)
- [ ] Реализовать scheduled-сканер (аналог apscheduler + management-команд Django).
- [ ] Кросс-платформенный обход больших директорий и добавление книг по расписанию.
- [ ] Вынести сканер форматов в плагины (fb2, epub, pdf и др).

### 10. Локализация и конфигурирование (неделя 9)
- [ ] Поддержка мульти-языка (сообщения, названия, описание).
- [ ] Админ-консоль для всех основных конфиг-параметров (аналог Django FConstance).

### 11. Тестирование, сравнение поведения, рефакторинг (неделя 10)
- [ ] Провести полное автотестирование: JUnit + интеграционные тесты сервисов и API, UI.
- [ ] Сравнить главное поведение с Python-оригиналом (“smoke-тесты”).
- [ ] Прогнать все важные кейсы глазами пользователя и внешних клиентов OPDS/Telegram.

### 12. Документация и production-старт (неделя 11)
- [ ] Описать сборку и деплой, подготовить Dockerfile, docker-compose.yml.
- [ ] Описать админ-функции, описание плагинов, инструкцию по миграции и установке.
- [ ] Провести инструктаж для конечных пользователей.
